  understanding: "ClikB is an AI content creation system designed around human-in-the-loop control. The user does not just type a prompt and wait for a black-box result; PromptInput, NotepadEditor, Storybook, and EditStory keep exposing intermediate planning, scene, image, video, character, narration, and publishing decisions so the user can intervene at every major stage. The base creation entry is the golden prompt in PromptInput. The visible shell opens Notepad/NotepadEditor, where the prompt text is edited, brainstorm and template tools live, and music-specific scene timing is calculated when a Golden Music file has been selected. PromptToolbar wraps the creation surface with Styles, model selection, pixel cost/balance, Slideshow preview, Characters revisit, Music upload, and window controls. TitleSelector maps routes to modes: /images is Shorts, /kickit is Cinema/Stories, and /clikit is Games/Interactions. StartStory is the first real controller: it merges Vipcharacters into remixData as character descriptions, chooses /startMemes for type 0, /startStory for type 1, and /startInteractions for type 3, then receives keyPoints. In music video mode, type 1 with promptMusicUrl rewrites the planning request so the story must produce exactly promptMusicSceneCount scenes based on the song segmentation. Story/Cinema duplicates every returned keyPoint into adjacent Stage A and Stage B slots before StartPlan sends the keyPoints to /startPlan and stores Planx. After this, Storybook becomes the workshop. Before HD generation, it prefetches scene image prompts through ImageDesignStory or ImageDesignStoryStage, then fires cheap fluxschnell nano images in the background. These nano images create the 'using imagination' storyboard layer: they make every scene visually identifiable before expensive HD images exist and can also serve as placeholder/start-frame images for the Manual/Video path. Once prompts are prefetched, PromptInput shows a path choice overlay with Skip and Create Characters. Skip hides the character studio and lets Storybook continue. Create Characters runs the casting pipeline through /extractCasting and /generateCastingPrompts, merges VIP characters from WorldModel/direct upload/manual character input, and produces referenceImages for later character injection. In Storybook, Auto means generate the actual HD images sequentially using the selected image model and active scene characters. Manual/Video mode sets the app up so nano images can stand in as scene images while the user manually uploads or regenerates images, or continues to video with nano start frames; this is intentional creative freedom for image-only, video-only, or mixed workflows where allowed. The major Storybook stages are image mode, video mode, and B-shot mode. Continue saves/uses the images and moves to video mode. In video mode Storybook creates PlanVid through /startPlanVid, passes it to EditStory, and the main button becomes Next for normal content or Debut for music video mode. Next opens B-shot mode for normal Shorts/Cinema flows; music video mode does not use B-shots and publishes from video mode through PublishLoader/PublishLoader2. B-shots are supporting cutaways/reactions attached around A-shots. With narration in Story/Cinema, B-shots are calculated around Stage B and audio duration; without narration or in Shorts-like flows, default B-shot placeholders can be created. B-shot prompts use the base visual prompt and previous video prompt context, then generate their own nano images. EditStory is the workhorse workstation. It receives unified A-shot/B-shot data from Storybook: GeneratedText, GeneratedTextx, TextVideo, ImagesHdCloud, VideoArrayCloud, nanoImages, referenceImages, detectedCharacters, Vipcharacters, PlanVid, timing, music mode props, and model settings. Image mode exposes Update with AI, Scene Image Prompt, Enhance/Safety/Recreate style controls, active character circles, and per-scene regeneration. Video mode exposes a horizontal model list, duration, audio toggle, Auto Prompt, video prompt text, generated video controls, reference video/lip-sync tools, and character injection. Auto Prompt requires a selected video model; it uses PlanVid, scene text, image description, duration, targetModel, ratioKey, and imageUrl to call VideoDesign or GptVideoVisualMiniMax, then fills TextVideo. GenerateVideox maps selected video models to backend routes such as veo3fast, sora2, minimax23Route, Seedance2, KlingRouteo1, minimax23Routex, omniHuman, or klingPro, and sends active character/action/motion images as activechracterimages and activechracternames. The audio toggle is represented by musicKling/generateAudio/useaudio, because some video models generate native audio and others should be run without audio. EditStory also has Action Image Generation and Motion Storyboard Generation. Action images let a user create one specific action reference frame, such as a character jumping over a car instead of standing near it; the action prompt can include @Character handles so selected character images become sampleImages. Motion storyboard turns the current video prompt into a multi-panel grid image through GptRemakeText and then an image model, giving newer video models a complete storyboard reference for long or complex movement. Games/Interactions are a special caveat. The /clikit route runs PromptInput with type 3 and StartStory calls /startInteractions. GptInt returns node-labeled keyPoints with root, branches, victory, and failure/game-over structure. Generated videos are stored in localStorage slots and localInteractionpostId, then Clikit opens InteractInput. InteractInput offers Touch and Swipe authoring using DefaultStageUI, TouchEditStageUI, TouchPreviewStageUI, SwipeEditStageUI, and SwipePreviewStageUI. The user places hotspots, picks branch videos, adds audio, previews, and saves through /interactionSave, so this mode is video-only and goes to the interaction creation tool rather than the normal final publish flow. Final publishing for non-interaction content is handled through PublishLoader and PublishLoader2. PublishLoader manages preflight/narration/music choices and can hand off music-video publishing. PublishLoader2 receives images, videos, audio, B-shots, music settings, clip duration, music segments, ratio, and Lambda status. The backend/cloud processing assembles the final scripted MP4 with the selected scene media, narration/music, and optional B-shot material.",
